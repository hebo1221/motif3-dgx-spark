# Motif 프로젝트 가치 보완 결과

2026-09-05 · DGX Spark / GB10 · 실험용 공개 버전 v1.3.0-rc.1

개인 경로·장치 식별자를 정리한 공개본이다. 원래 기록의 해시와 공개 파일의 해시는 다를 수 있다. [공개본의 출처와 재현 범위](PUBLICATION.md)를 먼저 확인한다.

**이번에 보완한 것은 다른 개발자가 재사용할 수 있는 수치 검사기와, 질문 대상·원문 근거·종료 한도를 지키는 문서 실행기다. Motif를 신뢰할 수 있는 범용 에이전트로 완성한 것은 아니다.** 실제로 나아진 부분과 여전히 실패하는 부분을 모두 실행 기록에 연결했다.

## 실제로 추가한 가치

| 부족했던 점 | 구현·검증한 보완 | 현재 의미 |
|---|---|---|
| 큰 Motif 모델이 있어야 배치 수치 문제를 조사할 수 있었음 | **모델 없이 실행하는 Q8_0 행렬 검사기**, 고정 토큰 재생 검사기 | 다른 개발자가 작은 재현부터 시작할 수 있음 |
| 큰 기존 CUDA 수정의 효과를 분리하기 어려웠음 | **두 파일만 바꾸는 선택형 기준 패치** | 확인한 6개 조건·147,456개 값에서 한 열씩 계산한 결과와 정확히 일치 |
| 질문한 프로젝트와 다른 문서를 읽고도 정답처럼 보고함 | 프로젝트 색인·문서 해시·검색 및 열람 범위 검사 | 알려진 HELDOUT-020 실패는 두 모델 모두 올바른 문서의 K39271로 수정 확인 |
| 인용 ID만 있고 원문 확인이 불편했음 | 원문 행 선택과 프로그램의 직접 인용, 읽기 쉬운 보고서 출력 | 답변과 실제 구절을 함께 검토할 수 있음 |
| 잘린 답이나 계속되는 자료 탐색을 종료하지 못함 | 끝맺음 검사·제한된 수정 기회·마지막 단계 보고 제한 | 미완성 답을 성공으로 처리하지 않음. 모델의 반복·사실 오류는 여전히 남음 |

수치 패치는 **속도 개선판이 아니다.** 확인한 조건에서는 기존 배치 경로보다 약 1.92–5.18배 오래 걸렸다. 빠른 구현을 만들 때 정답을 비교하는 단순한 기준으로 쓸 수 있다. 기본 경로의 출력은 9개 조합에서 유지됐으며, 원래 라이브러리로 복구한 출력도 같았다. 다른 GPU나 전체 모델의 모든 경로를 검증하지 않았다. [수치 검사와 작은 패치](runtime/README.ko.md).

## Motif를 쓸 이유는 더 구체적으로 확인했다

기존 단순 문서 조회 100문항과 별도로, 실제 프로젝트 보고서를 읽고 주장·측정 조건을 해석하는 질문 8개를 사전에 고정해 실행했다. 아래는 **요구한 설명을 모두 충족했는지에 대한 assistant의 엄격한 내용 검토**다. 독립 사용자 평가나 일반 모델 순위가 아니다.

| 확인용 v3 · 8개 질문 | Motif IQ2 + MTP 1 | Qwen3-8B Q8_0 |
|---|---:|---:|
| 형식·출처 검사를 통과한 답변 | 7 | 8 |
| 요구사항 완전 충족 | **4** | **0** |
| 부분 충족 | 3 | 3 |
| 실패 | 1 · 답변 전에 단계 소진 | 5 · 중요한 오판 또는 근거 없는 주장 |
| 질문별 시간 중앙값 | 70.04초 | 16.52초 |

Qwen은 5,560개 토큰 일치를 Motif와 Qwen 두 모델 간 출력 일치로 잘못 설명했고, 냉시작 비교로 사용할 수 없다는 자료를 사용할 수 있다고 답했다. Motif는 이 두 판단과 과장된 공개 문구를 더 잘 구분했다. 그러나 설명 누락과 잘못된 본문 행 번호가 있었고, 한 질문에서는 필요한 문서를 읽고도 계속 탐색하다 답변을 만들지 못했다.

**이 결과는 Motif가 보고서 해석의 후보가 될 근거이며, 자동 업무를 맡겨도 된다는 근거는 아니다.** 문서 다섯 개와 서로 연관된 질문을 사용했고, 같은 assistant가 질문 작성과 내용 검토를 했다. 완전 충족 0개가 Qwen의 모든 설명이 틀렸다는 뜻도 아니다. 누락 때문에 부분 통과한 답변을 따로 남겼다. [질문별 판정](REVIEW.ko.md), [평가 방법](EVALUATION.ko.md).

## 재검사에서 남은 문제도 기록했다

확인용 v3는 그대로 보존했다. 이후 최종 **v4**에 마지막 단계 보고 제한을 더하고 알려진 질문 세 개를 다시 실행했다. Motif는 대상 혼동을 해결했지만, 다른 질문에서는 미완성 보고서를 똑같이 반복해 중단했다. 두 보고서를 종합한 답변은 문장 끝까지 나왔으나 BF16 원본 크기를 **629.69 GB가 아닌 89.72 GB**로 잘못 적었다. Qwen은 세 답변을 만들었지만 두 답변에 필요한 설명이 빠졌다.

따라서 이번 수정으로 일반적인 오류 회복이나 사실 정확성이 해결됐다고 보고하지 않는다. 기존 100문항의 Motif 99/100 점수도 변경하지 않았다. [수정 후 별도 검토](evidence/repair-semantic-review.json), [잘못된 답을 포함한 예제](examples/README.ko.md).

## 사용과 전달

- [사용 방법](USAGE.ko.md): 내 Markdown 문서를 색인하고, 한 번 실행한 뒤 원문이 붙은 답변을 검토한다.
- [검토용 기준 답변](REFERENCE-ANSWERS.ko.md): 확인 질문의 올바른 비교 대상·조건을 원문 위치와 연결했다. 평가 후 작성한 검토 가이드이며 새 시험 자료가 아니다.
- `client/`: 최종 v4. 대상과 원문 확인, 종료 제한을 포함한다.
- `runtime/`: 두 검사기의 소스, 작은 CUDA 패치, 빌드·재현 방법이다.
- `evidence/`, `evaluation-source/`, `workflows/`: 초기 실패, 버전별 소스, 고정 자료와 실제 응답이다.

공개 사용 절차는 [사용법](USAGE.ko.md)에 있다. 자신의 로컬 도구 호출 서버와 문서를 지정해서 실행한다.

최종 v4 경계 검사 **30개가 Mac과 Spark에서 통과**했다. 기존 완료 기록 17개를 모델 없이 재생해 요청·실행·보고서가 유지됨을 확인했다. 모델 없는 Q8 시험의 복구 비교, 실제 로딩 라이브러리와 해시, 문서 색인 도구와 보고서 출력도 확인했다. [최종 Spark 점검](evidence/final-audit.json)에서 원본과 후보 파일의 결속이 유지됐고, 소유 서버·GPU 연산 프로세스·8825 포트 리스너가 남아 있지 않았다.

원본 BF16과 IQ2의 작업 품질 비교, 범용 코딩 에이전트, 다른 GPU의 CUDA 동작은 미검증이다. 가중치·바이너리는 포함하지 않았다. 전체 CMake 재빌드는 수행하지 않았다. 이번 공개는 가중치를 교체하지 않는 코드·검증 자료 공개다.
