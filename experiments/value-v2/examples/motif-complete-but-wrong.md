# 검토할 답변

motif-runtime과 motif-agent-current를 모두 검토한 결과, 네이티브 도구 호출은 두 문서에서 모두 수정 단계로 기술된다. motif-runtime에서는 공개 direct IQ2 모델에 최종 토크나이저와 MTP를 통합했으나, 네이티브 강제 도구 호출은 여전히 FAIL 상태이며, 생성 접두부와 required 호출 문법 문제만 분리 검증한 단계다. motif-agent-current에서는 도구 호출 파서를 고치고 Qwen3-8B Q8_0과 비교해 100문항에서 99건·100건을 맞혔으나, 원본 BF16 품질 보존은 입증하지 않았다고 명시한다. 원본 BF16 품질 보존은 motif-runtime에서 89.72 GB BF16 원본의 제한 검사 결과 300초 안에 서버가 준비되지 않았고 0건의 추론 요청만 수행돼, 이번 작업에서 IQ2가 원본 품질을 보존한다거나 개선했다고 말할 수 없다고 결론짓는다. 따라서 네이티브 도구 호출 수정은 motif-runtime과 motif-agent-current 모두에서 진행 중이나, 원본 BF16 품질 보존은 입증되지 않았다.

## 확인한 원문

### motif-agent-current · 5–5행

> **네이티브 도구 호출 문제를 수정하고, 로컬 문서를 검색·열람·계산해 인용과 함께 답하는 실행기를 만들었다. 이 문서 업무의 기본 모델은 Qwen3-8B Q8_0으로 정했다.** 같은 고정 100문항에서 Motif IQ2는 99건, Qwen은 100건을 맞혔고, Qwen의 전체 처리 시간은 약 3.3배 짧았다.

원문 SHA-256: `57a8e523f182a0b672c3a558b15058d66e82436eb112f4de7fef66cf822bcce8`

### motif-agent-current · 50–52행

> 기존 629.69 GB BF16 원본을 mmap과 CPU MoE offload로 시작하는 제한 검사를 수행했다. **300초 안에 서버가 준비되지 않았고 추론 요청은 0건**이었다. 해당 프로세스는 종료했다. 이 결과는 이번 시간 한도에서 시작하지 못했다는 뜻이며, 메모리 부족이 입증됐다거나 원본 실행이 불가능하다는 뜻은 아니다.
> 
> 따라서 이번 작업으로 IQ2가 원본 품질을 보존한다거나 품질이 개선됐다고 말할 수 없다. Qwen 비교는 이 고정밀 대조를 대신하지 않는다. 이전에 관찰한 범용 코드 생성의 반복 문제도 이번 문서 도구 프로필로 해결됐다고 주장하지 않는다. [BF16 제한 검사](evidence/bf16-canary-v1/receipt.json).

원문 SHA-256: `57a8e523f182a0b672c3a558b15058d66e82436eb112f4de7fef66cf822bcce8`
