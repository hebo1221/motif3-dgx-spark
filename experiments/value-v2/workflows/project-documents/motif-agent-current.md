# Motif-3 에이전트 준비 검증

2026-09-05 · DGX Spark / NVIDIA GB10 · 비공개 검증·실행 패키지

**네이티브 도구 호출 문제를 수정하고, 로컬 문서를 검색·열람·계산해 인용과 함께 답하는 실행기를 만들었다. 이 문서 업무의 기본 모델은 Qwen3-8B Q8_0으로 정했다.** 같은 고정 100문항에서 Motif IQ2는 99건, Qwen은 100건을 맞혔고, Qwen의 전체 처리 시간은 약 3.3배 짧았다.

현재 판정은 **사람이 근거를 확인하는 문서 보조 파일럿 준비 완료**다. 범용 에이전트, 자동 업무 완료 보증, IQ2의 원본 품질 보존은 입증하지 않았다. 실험용 공개 후보에 필요한 코드와 실패를 포함한 검증 자료를 묶었으며, 새 공개·업로드·커밋은 하지 않았다.

## 같은 업무에서 확인한 차이

| 고정 100문항 | Motif direct IQ2 + MTP 1 | Qwen3-8B Q8_0 |
|---|---:|---:|
| 정답 | **99/100** | **100/100** |
| 코드 조회 | 24/25 | 25/25 |
| 계산 / 정보 없음 / 두 사실 조회 | 각각 25/25 | 각각 25/25 |
| 전체 업무 시간 | 2,006.18초 · **33.4분** | 605.36초 · **10.1분** |
| 업무 시간 중앙값 | 18.30초 | 5.80초 |
| 표본 p95 | 27.06초 | 7.65초 |
| 모델 파일 | 89.72 GB | 8.71 GB |
| 중간 도구 오류가 발생한 업무 | 0건 | 25건 · 모두 회복 후 정답 |

두 모델이 모두 맞힌 99문항에서도 Qwen이 전부 더 빨랐다. Qwen의 중간 오류는 문서 이름을 ID로 바로 읽으려다 거절된 뒤 검색으로 실제 ID를 찾아 회복한 경우다. 정답 100건이 모든 중간 선택까지 완벽했다는 뜻은 아니다.

시간은 한 모델 서버가 준비된 뒤 실제 검색·열람·계산·답변에 걸린 합계다. 한 슬롯, thinking off, greedy, prompt cache off 조건이다. 모델과 템플릿이 다른 두 실행 구성의 비교이며, 양자화 비트 수만 바꾼 비교가 아니다. 서버 준비 시간은 별도 기록했고 운영체제 파일 캐시를 통제한 냉시작 비교로 해석하지 않았다.

100문항은 **네 가지 업무 형식에 사실을 바꿔 넣은 합성 사례**다. 100종의 실제 사용자 업무나 모집단 성능을 대표하지 않는다. Qwen은 기본 파서의 개발 검사 실패를 고친 뒤 같은 문항으로 비교했으며, 이전 일부 실행도 보존했다. 처음 보는 독립 시험에서 100점을 받았다는 주장으로 사용하면 안 된다. [전체 집계](evidence/validation-summary.json), [방법과 범위](EVALUATION.md).

## 출처가 있어도 틀릴 수 있었다

Motif의 `heldout-020`은 020 프로젝트의 확인 코드를 물었다. 모델은 프로젝트를 빼고 “확인 코드”만 검색한 뒤 002 문서를 읽고 `K38232`를 반환했다. 기대 답은 020 문서의 `K39271`이었다. 도구와 인용은 실제였지만 질문의 대상이 달랐다.

이 실패를 고쳐 같은 문항을 다시 통과한 것으로 보고하지 않았다. 다음 보완의 첫 항목은 **질문 대상과 문서 대상의 일치 확인**이다. 이 한 건만으로 IQ2 양자화가 원인이라고 단정할 수도 없다. [실패 원시 기록](evidence/iq2-heldout-v1/heldout/heldout-020.json).

전달용 실행기로 과거·현재 프로젝트 문서 두 개를 함께 읽는 업무도 수행했다. Qwen은 두 문서를 읽고 인용하며 “호출 문제는 개선됐지만 원본 품질 보존은 미검증”이라고 완결된 답을 냈다. 업무 시간은 11.34초였다. Motif는 핵심 판단과 두 인용을 맞혔지만 320자 상한에서 마지막 문장이 끊겼다. 업무 시간은 32.91초였으며, 완성도는 부분 통과로 기록했다. [답변 검토](evidence/qualitative-review.json).

## 구현과 검증

- **도구 호출 파서:** Motif의 생성 접두부와 required 호출 문법을 고쳤다. 지정 프로필에서 강제 호출 전에 일반 문장을 길게 생성하거나 단일 호출 조건에서 두 번째 호출을 붙이지 못하게 했다. 기존 기본 템플릿은 유지했다.
- **Qwen 비교 조건:** 기본 파서에서도 일반 문장과 복수 호출을 허용하는 경로가 재현됐다. 공식 메시지 형식을 유지하는 별도 옵션 파서로 같은 제약을 적용했다. 초기 실패와 수정 후 결과를 분리해 보존했다.
- **실제 API:** 두 수정 구성 모두 네이티브 진단 40/40, 스트리밍 호출 4/4, 개발 업무 8/8, 문서 속 지시문·역할 표기·가짜 도구 결과 검사 3/3, 기존 프로젝트 보고서 조회 2/2를 통과했다. 이것은 해당 사례의 결과이며 일반 공격 내성을 보증하지 않는다.
- **호출·실행 경계:** 잘린 응답, 알 수 없는 도구, 추가·중복 인자, 읽지 않은 문서 인용, 동일 호출 반복을 차단한다. 문서는 지정 폴더의 Markdown만 읽고 계산기는 제한된 산술식만 처리한다. 모델이 파일을 쓰거나 명령·외부 요청을 실행하는 도구는 없다.
- **검사:** 어휘만 읽는 파서·문법 검사 24/24와 기존 전체 chat 회귀 검사가 통과했다. 전달용 클라이언트는 경계 검사 14/14를 통과했다.

고정 100문항을 수행한 원본 클라이언트는 `evaluation-source/`에 보존했다. 정적 점검에서 별도로 발견한 잘못된 계산식의 예외 처리를 전달용 클라이언트에 보완했다. **기록된 226개 업무를 새 모델 호출 없이 재생한 결과, 보완 전후 호출·실행 결과·인용·보고서가 일치했다.** 이것은 새 정확도 측정이 아니며, 전달용 버전의 실제 실행은 앞의 두 문서 업무로 따로 확인했다. [수정 차이](agent-calculator-error-v1.patch), [재생 검증](evidence/release-replay.json).

`answer_produced`는 형식과 출처 검사를 통과한 보고서가 생겼다는 뜻이다. 사실 정확성은 별도의 평가 결과다. 도구가 실행됐는지는 `steps`, 읽은 문서의 정체는 `source_receipts`에서 확인한다.

## 원본 품질 비교는 아직 보류

기존 629.69 GB BF16 원본을 mmap과 CPU MoE offload로 시작하는 제한 검사를 수행했다. **300초 안에 서버가 준비되지 않았고 추론 요청은 0건**이었다. 해당 프로세스는 종료했다. 이 결과는 이번 시간 한도에서 시작하지 못했다는 뜻이며, 메모리 부족이 입증됐다거나 원본 실행이 불가능하다는 뜻은 아니다.

따라서 이번 작업으로 IQ2가 원본 품질을 보존한다거나 품질이 개선됐다고 말할 수 없다. Qwen 비교는 이 고정밀 대조를 대신하지 않는다. 이전에 관찰한 범용 코드 생성의 반복 문제도 이번 문서 도구 프로필로 해결됐다고 주장하지 않는다. [BF16 제한 검사](evidence/bf16-canary-v1/receipt.json).

## 프로젝트의 다음 가치

1. **문서 보조의 기본값은 Qwen으로 운영한다.** 현재 확인한 업무에서 더 짧은 시간과 작은 파일로 목적을 달성했다. 처음에는 사람이 인용과 대상을 확인하는 방식으로 사용한다.
2. **질문·문서 대상 일치와 실제 업무 자료를 먼저 보강한다.** 유사한 이름, 변경된 버전, 여러 문서의 종합을 포함한 실제 질문 30개를 개선용 10개와 확인용 20개로 나눈다.
3. **속도는 반복 문맥의 재사용부터 살펴본다.** 이번 Motif 100문항에서 서버 처리 시간의 약 70%가 입력 처리였다. 캐시를 켰을 때의 효과와 정확성은 별도 검증이 필요하다.
4. **Motif의 추가 이점이 나타나는 업무를 찾은 뒤 양자화를 개선한다.** 고정밀 비교 없이 재양자화부터 반복할 근거는 부족하다. Spark에서 큰 모델을 실행하고 실제 도구 호출까지 검증한 코드·재현 자료 자체는 프로젝트의 공개 자산이 된다.

구체적인 파일럿 진행 기준은 [PILOT.ko.md](PILOT.ko.md)에 있다.

## 바로 사용하기

Spark의 실행기 위치:

```text
/opt/motif-work/motif3-quant/campaigns/agent-readiness-v1/release-client-v1
```

기본 설정은 상위 폴더의 `config.default-agent.json`이며 Qwen을 선택한다. `config.agent.json`은 Motif 실험용이다. 실행기는 업무 하나를 수행한 뒤 자신이 띄운 모델 서버를 종료한다. 명령과 문서 형식, 제한은 [USAGE.ko.md](USAGE.ko.md)에 있다.

가중치와 바이너리는 이 패키지에 포함하지 않는다. 측정 런타임은 기존 빌드의 객체 파일을 재사용해 공용 채팅 라이브러리만 분리해 다시 만든 구성이다. 새 패치의 전체 CMake 재빌드는 수행하지 않았다. [Motif 공개 파일](https://huggingface.co/jhkim55/Motif-3-Direct-IQ2-XXS-DGX-Spark), [고정한 Qwen 공식 리비전](https://huggingface.co/Qwen/Qwen3-8B-GGUF/tree/7c41481f57cb95916b40956ab2f0b139b296d974).

최종 점검에서 원본 모델의 검증 결속, 기존 소스·라이브러리, 두 후보 런타임, 고정 자료가 유지됐다. 모든 소유 모델 프로세스가 종료됐고 GPU 연산 프로세스와 8825 포트의 리스너가 남아 있지 않았다. 최종 100문항 실행의 장치 관측 오류는 없었으며, 앞선 MTP 개발 검사에서는 `nvidia-smi` 관측 시간 초과 한 건이 기록돼 있다. [최종 점검](evidence/final-audit.json).
