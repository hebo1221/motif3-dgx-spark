# Motif-3 공개 모델의 MTP 통합 검증

2026-09-05 · DGX Spark / NVIDIA GB10 · 내부 검증 패키지

**공개 direct IQ2 모델에 최종 토크나이저와 MTP를 통합했고, draft 1을 권장하는 실험용 실행 구성을 만들었다.** 11개 요청의 출력 토큰 5,560개가 가속 꺼짐·켜짐·복구 실행에서 모두 일치했다.

**판정: 통합 추론과 지정 성능 기준 PASS · 네이티브 강제 도구 호출 HOLD · 품질 개선 미검증.** 사전에 정한 API 포함 전체 기준은 통과하지 못했다. 대화·추론 실험용 성과와 도구 호출의 실패를 함께 공개할 수 있는 상태다.

## 새로 확보한 가치

1. 과거의 다른 IQ2 파일에 한정됐던 MTP 증거를 실제 공개 모델에 연결했다. 89.72 GB 전체 해시, 보조 모델 해시, 구조·토크나이저 배열을 새로 확인했다.
2. 최종 토크나이저와 MTP를 함께 빌드했다. 공식 토크나이저와 비교한 **434,569개 token ID**가 모두 일치했다. 12,011개 형식·Unicode 검사 사례와 두 기존 코퍼스를 포함한다.
3. 실제 HTTP 요청으로 draft 1·2·3을 비교해 더 나은 기본값을 찾았다. 속도와 동일 출력, 정상 종료·출력 상한, 첫 응답 시간을 함께 기록했다.
4. 재현용 빌드·모델 검사·실행 도구, 공개 가능한 합성 프롬프트, 원시 기록에 연결된 요약을 묶었다. 기본 검증 뒤 서버는 종료한다.
5. 도구 API 문제를 작은 CPU 프로그램으로도 조사할 수 있게 했다. 이 검사는 315B 가중치를 읽지 않는다.

## 확인된 시간 단축

Spark 내부 localhost HTTP 요청의 완료 시간 합계다. Target은 가속을 끈 전·후 실행의 평균이다. 모델 적재와 워밍업은 포함하지 않는다.

| 독립 확인 범위 | Target 평균 | MTP draft 1 | 요청 시간 감소 |
|---|---:|---:|---:|
| 일반 요청 6건, 출력 440토큰 | 30.86초 | 23.37초 | **24.3%** |
| 그중 자연 종료한 5건, 출력 184토큰 | 14.42초 | 11.92초 | **17.4%** |
| 다섯 문맥 깊이의 강제 생성, 5,120토큰 | 422.24초 | 306.19초 | **27.5%** |

일반 요청 6건에는 256토큰 상한에 도달한 코드 요청 1건이 포함된다. 자연 종료 5건의 수치는 이를 분리한 보조 분석이다. 미리 정한 설정 선택·성능 기준은 변경하지 않았다. 작은 고정 표본이므로 실제 사용자 모집단의 평균이나 p95를 추정한 값은 아니다.

| 입력 토큰 | 생성 토큰 | Target 평균 | MTP draft 1 | 시간 감소 | 토큰·종료 일치 |
|---:|---:|---:|---:|---:|---|
| 128 | 1,024 | 65.11초 | 42.35초 | 35.0% | 일치 |
| 512 | 1,024 | 66.37초 | 43.61초 | 34.3% | 일치 |
| 2,048 | 1,024 | 71.86초 | 49.09초 | 31.7% | 일치 |
| 8,192 | 1,024 | 94.05초 | 70.49초 | 25.1% | 일치 |
| 16,000 | 1,024 | 124.85초 | 100.65초 | 19.4% | 일치 |

다섯 강제 생성 요청의 서버 보고 생성 처리량은 Target 평균 **14.63 tok/s**, MTP **21.99 tok/s**였다. 입력 처리도 포함한 위 HTTP 완료 시간과는 다른 지표다. 스트리밍 한 이벤트에 여러 토큰이 실릴 수 있으므로 이벤트 간격을 토큰 간 지연으로 부르지 않았다.

## 설정을 고른 근거

선택용 네 요청에서는 MTP 후보 세 개 모두 354개 출력 토큰과 종료 방식이 일치했다. 같은 통합 런타임의 가속 꺼짐 전·후 요청 시간 합계 평균은 23.98초였다.

| Draft 최대 길이 | 네 요청 시간 합계 | 대조군 대비 감소 |
|---:|---:|---:|
| **1** | **17.84초** | **25.6%** |
| 2 | 18.17초 | 24.2% |
| 3 | 20.87초 | 12.9% |

이 작은 개발 표본에서 가장 짧은 시간을 보인 1을 선택했다. 1과 2의 차이가 작아 모든 작업에서 1이 최적이라는 주장은 하지 않는다. 이후 별도로 고정한 여섯 요청과 기존의 다섯 문맥 깊이를 앞뒤 대조군으로 확인했다.

## 런타임과 모델의 정확한 범위

- Target: 공개 BF16 직접 양자화 IQ2_XXS, 89,720,474,560 bytes. SHA-256 `9d6f7aee57f0271223f51d69c63d8576a259809e9f05e2ac596512e940c80c5a`.
- Sidecar: 기존 linked BF16 MTP, 512,363,040 bytes. SHA-256 `d813251f1b7e8158399352af6e44c92df2445cd807fda1a869d2247279806f81`.
- 기반 커밋: `cc3f13b3f172978d7b3c215780d4cc98bb0e1c80`. 최종 토크나이저 패치와 기존 MTP 런타임 패치를 순서대로 적용했다. 진단 패치는 이 빌드에 적용하지 않았다.
- GPU: 한 NVIDIA GB10. CUDA 13.0.88, GCC 13.3, ARM64, `121a-real` 빌드.
- 실행: GPU 전체 적재, FA on, f16 KV, 20 스레드, batch 2,048 / ubatch 512, 할당 context 22,016, 한 슬롯, greedy, seed 42, prompt cache off.
- 외장 SSD에서의 적재는 대략 92–94초였다. MTP 검증 중 `MemAvailable` 최저 관측치는 약 **29.9 GiB**였다. 통합 메모리에서 RSS와 GPU 할당을 합산하지 않았다.

**MTP의 비교 기준은 같은 통합 런타임의 target-only이다.** 토크나이저 패치만 넣은 동일 기반 대조본과 비교하면 입력은 같지만 네 개발 요청 중 두 답변의 표현이 달랐다. 각각 자기 전·후 실행은 재현됐다. CUDA 변경은 일반 한 토큰 생성 경로에도 영향을 줄 수 있으므로, 기존 런타임과의 완전 동일 출력이나 기존 품질 점수의 승계를 주장하지 않는다.

MTP 보조 모델은 새로 변환한 것이 아니다. 기존 H0v2 대상 변환 기록을 보존하고, 공개 direct IQ2에 대한 새 호환성·해시 기록을 만들었다.

## 도구 API와 품질에서 남은 문제

| 네이티브 API 합성 검사 | Target 전 / MTP / Target 후 |
|---|---|
| 대화 응답 형식과 종료 | PASS / PASS / PASS |
| JSON 스키마 응답 | PASS / PASS / PASS |
| 모의 도구 결과를 읽어 답하기 | PASS / PASS / PASS |
| `tool_choice=required`로 도구 호출 생성 | **FAIL / FAIL / FAIL** |

강제 호출 사례에서는 `tool_calls`가 없고, 실제 조회 없이 임의의 날씨를 서술하다 128토큰 상한에 도달했다. 도구는 실행하지 않았다. 세 실행의 이 잘못된 응답도 동일했다. 앞의 PASS는 해당 API 형식·종료 검사이며, 지시 준수나 도구 선택 정확도 점수는 아니다.

모델 없는 파서 검사에서 응답 시작 문자열의 `<|` 두 글자가 잘리는 경계를 발견했다. 추론에 필요하지 않은 training EOS 접미사를 제거한 별도 템플릿은 경계를 바로잡았다. 하지만 두 조건의 실제 모델 검사에서 **도구 호출은 계속 실패했다**. 따라서 수정 후보를 기본 템플릿으로 승격하지 않았다. 생성 문법은 호출 전에 긴 일반 텍스트를 허용하며, 파서는 불완전한 호출을 일반 내용으로 돌려줄 수 있다. 구조 수정만으로 API 문제가 해결됐다고 판단할 수 없다.

코드 요청도 512토큰까지 늘린 후속 검사에서 자기 설명을 반복하며 상한에 도달했다. 가속 꺼짐·켜짐에서 같은 결과였다. 양자화·원 모델·지시 형식 중 무엇이 원인인지는 고정밀 대조가 필요하다.

## 다음 가치 상승의 우선순위

1. **이번 성과를 재현 가능한 실험용 배포 후보로 제시한다.** 중심 근거는 공개 파일의 정체, 같은 통합 런타임에서의 토큰 일치, 독립 요청의 완료 시간이다. 도구 API와 품질 한계를 함께 둔다.
2. **도구 API는 작은 재현 사례부터 수정한다.** 생성 접두부, required 호출 문법, 부분 응답 처리, native `tool_calls`를 분리해 검증한다. 이 패키지의 CPU 검사기를 시작점으로 쓸 수 있다.
3. **고정밀과 IQ2를 30–60개 같은 문항에서 비교한다.** 한국어 판단, 호출 여부, 인자, 종료와 반복을 함께 기록한다. IQ2에만 나타나는 실패를 확인한 뒤 새 양자화 후보를 설계한다.
4. **일반화를 측정한다.** 현재 결과는 한 GPU·한 슬롯·greedy에 한정된다. 동시성, 다른 문맥과 GPU는 별도 후속 실험이다.

기존 104 GB 후보와 소형 보정의 탐색을 바로 반복할 근거는 이번 작업에서도 생기지 않았다. 현재 내부 저장소 여유도 약 3 GiB여서 추가 대형 파일 실험에는 공간 확보가 필요하다.
