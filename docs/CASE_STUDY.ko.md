# Motif-3 315B를 DGX Spark 한 대에서 돌려본 기록

[SSD 후속 실험과 최종 마무리](FINAL_REPORT.ko.md)

[English](CASE_STUDY.md) · [실제 답변 둘러보기](RECORDED_DEMO.md) · [저장소](../README.md)

**83.56 GiB · 생성 16.49 tok/s · 128 GB DGX Spark 한 대.**

시작은 Motif-3의 3,147억 파라미터 sparse MoE 핵심 모델을 128 GB Spark 한 대에서
돌려보는 것이었다. 혼합 IQ2_XXS로 양자화해 54개 층을 모두 GPU에 올렸다.
83.56 GiB는 모델 파일 크기이며, 위 속도는 토크나이저 수정 전에 측정했다.

실행한 뒤에 확인할 문제가 더 있었다. 같은 문장을 다른 토큰으로 읽었고,
여러 토큰을 한꺼번에 검증할 때 출력이 달라졌다. 문서 에이전트는 원문을 제대로
인용하고도 숫자를 틀리게 썼다. 압축 모델은 BF16 품질 유지 기준도 통과하지 못했다.

이 글에는 그 문제들을 확인하고 수정한 과정을 담았다. 바로 실행해 보려면
[설치 절차](../README.md#download-and-run)를, 모델 답변부터 보고 싶다면
[답변과 원문](RECORDED_DEMO.md)을 열면 된다.

## 메모리에 들어간다는 사실을 검증하기

공식 BF16 원본 155개 조각은 총 629.68 GB였다. 이를 BF16 GGUF로 변환한 뒤
한 번만 양자화했다. 큰 전문가 가중치는 IQ2_XXS로 저장하고, 다른 텐서는
메모리 예산 안에서 정밀도를 유지했다. 실제 저장량은 원소당 2.2805비트다.

최종 파일은 89,720,474,560바이트, 즉 83.56 GiB다. 54개 층을 모두 GPU에 올리고,
서버 상태와 실제 한국어 요청 완료를 확인했다. 깨끗한 공개 실행 코드로 조건별
다섯 번 측정해 pp512 평균 316.71 tok/s, tg128 평균 16.49 tok/s를 얻었다.

이 속도는 토크나이저 정밀 수정 전의 고정 실행 코드에서 측정했다. 파일 크기와
실행 메모리도 구분했다. 별도의 앞선 세 세션에서는 GPU/통합 메모리 최대 할당량
85,713 MiB를 관측했다.

근거: [변환 방법](METHOD.md), [벤치마크 원시 값](../evidence/clean_runtime_benchmark.jsonl),
[실행 확인](../evidence/clean_runtime_verification.json), [전체 수치](../evidence/public_metrics.json).

## 입력이 같아야 출력의 차이를 해석할 수 있다

서버가 실행돼도 입력을 다른 토큰으로 읽으면 비교가 흐트러진다. Motif의 여러
단어를 묶는 분할 규칙, 유니코드 범주, 추가 토큰 주변의 공백 처리를 구현했다.

공개 GGUF와 수정된 실행 파일에서 말뭉치·고정 난수 사례의 공식 토큰 ID
**434,569개가 모두 일치**했다. 토크나이저 소스가 같은 확장 검증 후보에서는
**4,164,390개가 일치**했고, 최종 공개 기반 빌드의 회귀 검사도 16개 모두 통과했다.
서로 다른 검증 범위이므로 하나의 실행 결과처럼 합치지 않았다.

이 수정은 입력 해석의 정확성을 확보한다. 양자화된 가중치 자체를 복원하지는 않는다.

근거: [토크나이저 패치](../patches/motif3-tokenizer-exact-v1.patch),
[검증 범위와 결과](../evidence/tokenizer_exact_v1.json).

## 가속하면서 같은 결과를 얻는지 확인하기

MTP는 다음 토큰을 미리 제안하는 기능이다. 이를 연결하면서 내부 상태, 캐시,
어휘 일치를 맞췄고, 여러 토큰을 한꺼번에 검증할 때 CUDA 계산 경로가 달라져
선택 토큰까지 바뀌는 문제를 다뤘다.

가속 꺼짐 → 켜짐 → 새 프로세스에서 다시 꺼짐 순서로 비교했다. 다섯 작업의
**5,120개 생성 토큰이 가속 실행과 복구 실행에서 각각 모두 일치**했다.
서버가 보고한 생성 속도는 **14.5872 → 17.5565 tok/s, 1.2036배**였다.

이 실험의 대상 모델은 다운로드 모델과 바이트가 다르고, MTP 보조 가중치는
배포하지 않는다. 위 수치를 첫 화면의 16.49 tok/s와 전후 비교로 붙일 수 없다.

후속 작업에서는 모델 없이 Q8 행렬 계산을 비교하는 작은 도구도 분리했다.
시험한 폭 2·4에서 값 147,456개가 기준 계산과 비트 단위로 일치했다. 다만 작은
참조 패치는 기존 경로보다 **1.92~5.18배 느렸다**. 계산 정확성을 조사하는
기준 구현으로 공개했고, 속도 개선으로 포장하지 않았다.

근거: [MTP 구현과 결과](MTP_EXPERIMENTAL.md),
[모델 없이 실행하는 수치 진단](../experiments/value-v2/runtime/README.md).

## 실패한 결과로 배포 범위를 정하기

고정된 49,152개 평가 토큰에서 BF16 대비 perplexity는 **1.4115배**,
평균 KL은 **0.4541**이었다. 실행 전에 정한 기준은 각각 1.10 이하와 0.10 이하로,
둘 다 실패했다. 일부 가중치의 정밀도를 올린 실험은 메모리와 속도 비용을
정당화할 만큼 업무 성과를 높이지 못했다. 작은 보정도 도구 사용에서 퇴행해
기본 모델에 넣지 않았다.

문서 에이전트에서는 더 알아보기 쉬운 실패를 남겼다. 답변이 BF16 원본을
**89.72 GB**라고 설명했는데, 함께 인용한 원문은 **629.69 GB**라고 적혀 있었다.
인용 문서도 잘못 귀속했다. 형식이 맞고 인용문이 실재해도 해석은 틀릴 수 있었다.

[실제 답변 둘러보기](RECORDED_DEMO.md)에서 유용한 답과 이 실패를 함께 볼 수 있다.
검증 도구는 파일과 원문 연결을 확인한다. 내용의 정답 여부까지 판정하지는 않는다.
소규모 탐색 과제만으로 Motif와 다른 모델의 일반적인 우열을 주장하지 않는다.

근거: [품질 결과](RESULTS.md), [채택하지 않은 보정](ENGINEERING_FINDINGS.md),
[문서 에이전트 평가](../experiments/value-v2/README.md).

## 무엇을 기여했고, 무엇을 가져다 쓸 수 있나

Motif-3를 학습한 주체는 Motif Technologies다. 실행 코드는 llama.cpp와 Chrono의
Motif 포트, 기존 GQA-5 작업에 기반한다. 이 프로젝트의 기여는 직접 양자화한
배포물, 토크나이저 수정, 실험용 실행 패치, 수치 진단 도구, 제한된 문서 에이전트와
그 검증 자료다. 개발과 분석에는 Codex의 도움을 받았다. [출처](../NOTICE.md)를 명시했다.

메모리가 제한된 장비의 모델 배포, 입력 정확성 검증, CUDA 수치 문제 분석,
대조 실험, 실패를 보존하는 평가 방법을 실제 파일로 확인할 수 있다.
모델을 사용할 사람은 [재현 절차](../README.md#download-and-run)를,
작업 자체를 검토할 사람은 [기록된 답변](RECORDED_DEMO.md)을 보면 된다.

탐색 연구는 마무리했고, 재현 오류와 근거 정정을 중심으로 유지한다. 추가 작업은
[프로젝트 종료 및 재개 기준](PROJECT_STATUS.md)에 따라 판단한다.
